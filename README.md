# FinControl — веб-сайт для учёта, анализа и управления личными финансами

Дипломный проект. Веб-приложение на **Python / Flask** с базой данных **SQLite**,
интерфейсом на **Bootstrap 5** и графиками **Chart.js**. Все библиотеки лежат локально
в `static/vendor`, поэтому сайт работает без интернета.

## Быстрый запуск

```bash
pip install -r requirements.txt
flask --app app seed      # (необязательно) демо-пользователь demo / demo123 с данными за год
python app.py             # сайт откроется на http://127.0.0.1:5000
```

## Возможности

| Модуль | Функции |
|---|---|
| **Авторизация** | регистрация, вход, выход, «запомнить меня», смена пароля, удаление аккаунта |
| **Главная панель** | общий баланс, доходы/расходы/сальдо месяца, график за 6 мес., структура расходов, бюджеты, цели, прогноз |
| **Операции** | добавление/редактирование/удаление доходов и расходов; фильтры по периоду, типу, счёту, категории, поиск; пагинация; экспорт и импорт CSV (Excel) |
| **Счета** | несколько счетов (карта, наличные, вклад), начальный остаток, автоматический расчёт баланса, переводы между счетами |
| **Категории** | свои категории доходов и расходов с цветом и иконкой (14 стандартных создаются при регистрации) |
| **Бюджеты** | месячные лимиты по категориям, индикация 80 % / 100 %, копирование бюджетов из прошлого месяца |
| **Цели** | накопительные цели, пополнение/снятие, срок и расчёт необходимого ежемесячного взноса |
| **Аналитика** | сводка за период, норма сбережений, динамика за 12 мес., структура доходов и расходов, расходы по дням и дням недели, прогноз, автоматические рекомендации |

## Структура проекта

```
finance-app/
├── app.py            # приложение Flask: маршруты (контроллеры), безопасность, команда seed
├── models.py         # модели БД (SQLAlchemy ORM)
├── analytics.py      # модуль анализа: сводки, динамика, прогноз, рекомендации
├── requirements.txt
├── templates/        # HTML-шаблоны Jinja2 (представления)
└── static/
    ├── css/style.css
    ├── js/app.js     # построение графиков
    └── vendor/       # Bootstrap, Bootstrap Icons, Chart.js
```

Архитектура — **MVC**: модели (`models.py`), представления (`templates/`), контроллеры (маршруты в `app.py`),
бизнес-логика анализа вынесена в отдельный модуль `analytics.py`.

## Схема базы данных

```
users ──< accounts ──< transactions >── categories >── users
  │                                         │
  ├──< budgets >────────────────────────────┘
  └──< goals
```

| Таблица | Поля |
|---|---|
| `users` | id, username, email, password_hash, currency, created_at |
| `accounts` | id, user_id → users, name, type (cash/card/deposit/other), initial_balance, color |
| `categories` | id, user_id → users, name, type (income/expense), color, icon |
| `transactions` | id, user_id → users, account_id → accounts, category_id → categories (NULL = перевод), type, amount, date, description, created_at |
| `budgets` | id, user_id → users, category_id → categories, month (YYYY-MM), limit_amount; уникальность (user, category, month) |
| `goals` | id, user_id → users, name, target_amount, current_amount, deadline, created_at |

Баланс счёта не хранится, а вычисляется: `начальный остаток + Σ доходов − Σ расходов`, что исключает рассогласование данных.

## Методики анализа (`analytics.py`)

- **Норма сбережений** = (доходы − расходы) / доходы × 100 %.
- **Прогноз расходов на месяц** = уже потрачено + средний дневной темп × оставшиеся дни.
  Темп считается за последние 90 дней без крупных разовых платежей (≥ 20 % среднемесячных расходов —
  аренда, крупные покупки), чтобы они не завышали прогноз.
- **Рекомендации** (правила): норма сбережений < 10 % / ≥ 20 % (правило 50/30/20); рост расходов
  по категории > 30 % относительно темпа прошлого месяца; превышение бюджета (80 % и 100 %);
  прогноз расходов выше доходов; доля одной категории > 40 %.
- Переводы между своими счетами в аналитике не учитываются.

## Безопасность

- пароли хранятся только в виде хэша (`werkzeug.security`, PBKDF2/scrypt);
- защита всех форм от CSRF (токен в сессии);
- доступ к данным только владельца (`own_or_404`) — пользователь не может открыть чужую операцию по ID;
- ORM SQLAlchemy с параметризованными запросами — защита от SQL-инъекций;
- автоэкранирование шаблонов Jinja2 — защита от XSS;
- проверка `next` при входе — защита от открытого редиректа.

Для реального развёртывания задайте переменную окружения `SECRET_KEY`
(и при желании `DATABASE_URL`, например PostgreSQL) и запускайте через gunicorn/waitress.
